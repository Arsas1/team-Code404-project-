# Аудит репозитория CODE 404

Проверка выполнена по ZIP-архиву репозитория, который был предоставлен для анализа. Изменения в удалённый GitHub-репозиторий этим архивом не отправляются.

## Что обнаружено

1. **Нет реализации приложения.** В репозитории есть документация и отчёты, но нет рабочего исходного кода помощника по планированию дня.
2. **Пустые файлы-заготовки.** `scripts/script.py`, `scripts/script.bat` и `scripts/scripts.sh` имеют нулевой размер; они ничего не выполняют.
3. **Пустые отчёты.** `practical-works/practical-work-01/report.md` и Markdown-файлы для практических работ № 3–8 пусты. В папке № 1 при этом есть отчёт Word.
4. **Пустой `.gitignore`.** Добавлены базовые исключения для Python, IDE, временных файлов и локальных секретов.
5. **README не объяснял состояние проекта.** Теперь в нём явно указано, что приложение пока не реализовано, чтобы не создавать ложное впечатление о готовом продукте.
6. **Документ RACI был представлен только изображением.** Добавлено текстовое объяснение обозначений R/A/C/I и подпись к изображению.
7. **В описании ролей есть несогласованность, требующая решения команды.** В README Шувалов Арсений указан как архитектор ПО, а в эссе в `roles-and-responsibilities.md` сказано, что он совмещает роли архитектора и тестировщика. В том же документе Гужавин Александр указан как тестировщик. Команде нужно согласовать формулировки; аудит не выбирает роль вместо участников.
8. **В отчёте № 2 есть редакционные недочёты.** Повторяется предложение о регистрации участников; ссылка на матрицу RACI записана как `docs/rac-i-matrix.md`, тогда как фактическое имя файла — `docs/raci-matrix.md`. Перед сдачей исправьте исходный отчёт Word и Markdown-версию согласованно.

## Что улучшено в этой версии

- README переписан: добавлены статус проекта, структура, ссылки на документы и понятный порядок внесения изменений.
- Добавлен `.gitignore` с типичными исключениями для Python и локальных файлов.
- Документ RACI получил заголовок, расшифровку терминов и подпись к изображению.
- Добавлен этот файл аудита, чтобы команда могла закрыть найденные вопросы перед сдачей.
